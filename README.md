# Cashly

Android 14+ 原生离线记账应用。Kotlin / Compose Material 3 / Navigation / Room / DataStore。

## 使用

1. 安装 `app/build/outputs/apk/debug/app-debug.apk`（个人测试版本，使用 Android debug 签名）。
2. 打开「首页 → 开启自动记账」，阅读说明后到系统设置授权 Cashly 通知访问。部分手机侧载应用需先在应用信息中允许受限制的设置。
3. 手动记账不需要任何权限。通知记录不完整时，在「我的 → 导入账单」选择微信或支付宝导出的未加密 CSV / XLSX。
4. 核对预览中的时间范围、有效条数、异常及疑似重复项。异常行必须修正后重新导入；疑似重复逐笔选择新增或合并。
5. 定期通过「完整备份」保存 JSON。备份是明文财务数据，需自行妥善保管；恢复会在确认后覆盖当前账本。

## 数据与识别范围

- 不请求互联网权限，不做账号、云同步和 MySQL 连接。数据库名 `db_cashly`，金额用整数分。
- 只处理包名 `com.tencent.mm`、`com.eg.android.AlipayGphone`；微信通知还要求支付服务类标题，避免把普通聊天当作付款凭据。
- 只自动入账明确成功、金额唯一且方向明确的模板。其余疑似交易进入待确认；失败、待付款和营销文本忽略。
- 相同通知活动实例的更新共用来源 ID；通知被移除后，相同系统键允许产生新的交易。若第三方把多笔交易压缩到同一个持续更新的通知中，后续交易可能无法单独捕获，请用账单核对。
- 通知无平台交易时间时使用接收时间并标记，可编辑修正。内部转账不计收支，退款计入收入，不抵减支出（已有退款记录也按此口径统计），未确定原单的退款保留未关联状态。
- 退款收入的备注自动注明「退款」，原备注保留；已有退款记录启动时补充，列表和详情均可查看。
- 原始通知文本最多保留 30 天的清理窗口：接收通知、打开应用及系统定期后台任务时清理。Android 可能延迟后台任务，应用无法承诺在系统强制停止期间按秒删除；下次启动立即清理。备份不包含原始通知文本。
- 财务数据被显式排除在系统云备份及设备转移备份之外。应用卸载会删除本机账本。
- 默认分类只在空数据库首次初始化。其他为系统兜底分类；其他分类可新增、重命名，删除时迁移账目。

## 导入格式（待真实导出样本验证）

当前识别以下列名组合，前面的账单说明行会跳过：

| 字段 | 可识别列名 |
|---|---|
| 时间 | 交易时间 / 交易创建时间 |
| 金额 | 以「金额」开头的列 |
| 方向 | 收/支 / 收支 |
| 状态 | 当前状态 / 交易状态 |
| 对方 | 交易对方 |
| 交易号 | 交易单号 / 交易号 |
| 备注 | 商品 / 商品名称 / 商品说明 |

CSV 支持 UTF-8（可带 BOM）和 GB18030、引号内逗号/换行。XLSX 支持共享字符串与内联字符串，交易时间须为文本日期 `yyyy-MM-dd HH:mm:ss`（也支持分钟精度），不接受公式、加密文件、外部实体和 Excel 数值日期。文件及解压 XML 总量限制为 24 MB。

未知状态和不明确方向会成为异常行，不自动把所有「不计收支」交易认定为本人互转。退款汇总非零、原支出标记已退款等情况需独立明细或手动核对。转账、红包、提现等真实导出变体需提供脱敏样本后扩充适配。CSV 导出供阅读使用，与账单导入格式不同；恢复使用 JSON。

## 构建与测试

需要 JDK 21、Android SDK 36.1；工程保留 Gradle wrapper / AGP 9.1.1，Kotlin 使用 AGP 内置支持。

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
.\gradlew.bat :app:connectedDebugAndroidTest
```

Room v1 schema 保存在 `app/schemas`；未来变更数据库结构必须提高版本并添加显式迁移，禁止破坏性重建用户账本。

测试内交易和通知全部是合成数据，详细验证记录见 `VALIDATION.md`。
